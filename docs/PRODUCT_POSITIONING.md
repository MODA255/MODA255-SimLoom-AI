# SimLoom AI 产品定位

SimLoom AI 的核心任务是**操作工程软件并把工程流程串起来**。它面向
CATIA、Ansys、Adams 和 VI-grade 提供统一的 AI 入口、任务编排、软件适配、
结果回收、独立验证和审计能力。它不以重新实现这些软件的专业建模器、网格器、
求解器或行业数据库为产品主线。

## 系统边界

| 层 | SimLoom AI 负责 | CATIA / Ansys / Adams / VI-grade 负责 |
| --- | --- | --- |
| 目标与计划 | 解析自然语言目标、拆分阶段、管理依赖、选择已配置动作 | 按软件语义执行具体工程操作 |
| 输入与调用 | 准备副本、传递参数、生成或绑定脚本、启动 Windows worker/COM/厂商命令 | 接收软件原生模型、脚本和工况 |
| 原生工程操作 | 通过 adapter 调用参数更新、建模、网格、求解、导出等动作 | 真实创建和修改 CAD、网格和仿真模型；执行真实求解 |
| 结果与证据 | 回收原生文件、日志、指标和版本快照；检查文件完整性和声明的工程规则 | 产生原生模型、网格、求解结果、报告和软件状态 |
| 可视化 | 提供跨软件资产索引、预览、指标图、时间线和差异查看 | 提供软件内部完整的建模、网格和仿真后处理体验 |
| 失败处理 | 记录失败证据，执行工程师预先声明的有限修复和重规划 | 返回真实错误、收敛状态和模型上下文 |

## 运行方式

项目中的同一套计划可以在四种状态下运行：

1. **计划**：只生成步骤、参数和动作绑定，不触碰软件。
2. **排练/离线**：使用 fixture 验证文件、事务、验证器和 UI 流程，不宣称是真实软件结果。
3. **Windows worker**：通过 COM、厂商脚本或已配置命令操作本机安装的软件。
4. **结果回收**：从原生软件读回模型或结果文件，再进行独立检查和工程判定。

离线几何、OpenCascade、DXF 编辑和轻量 viewer 属于辅助能力。它们用于预览、输入准备、
格式转换、独立校验和没有商业软件时的开发测试；它们生成的 surrogate 不能替代真实软件
产生的工程证据。

## 产品成功标准

SimLoom AI 是否做得好，首先看工程师能否用更少的重复操作完成真实软件任务：

- 能否把目标准确映射到正确的软件、模型、脚本和工况；
- 能否安全地操作副本、锁定会话、等待长任务并在断线后继续查询；
- 能否确认软件确实保存、求解并导出了声明的原生结果；
- 能否把失败定位到软件动作、输入、参数、收敛或工程规则；
- 能否让工程师查看、比较、复核并接管每一次 AI 修改。

因此，AgentCAD 的二维 CAD 能力是交互、operation、验证和追溯可靠性的参考，
不是要求 SimLoom AI 重新做一个通用 CAD 软件。后续开发应优先补真实四软件的动作、
读回和验收证据，再按实际项目需要扩展本地辅助能力。
