# SimLoom AI 工程化路线图

SimLoom AI 的目标不是把四个商业软件重新做一遍，而是让工程师用一个稳定的入口完成：

```text
目标 → 计划 → 执行 → 结果 → 判定 → 可追溯交付
```

每一层都必须能在没有商业软件的机器上测试，并且在 Windows 工作站接入真实软件后保持
相同的工程对象、事务和验证边界。

## 当前最重要的产品原则

1. **默认可运行**：第一次启动就能创建项目、运行离线闭环、看到模型和指标。
2. **状态可解释**：用户始终知道当前是离线 surrogate、已连接、排练还是实际执行。
3. **失败可恢复**：每个写操作都有事务、日志、重试和 rollback；错误要告诉用户下一步。
4. **结果可审计**：输入、脚本、结果、规则、版本和哈希必须能一起导出。
5. **真实软件是执行权威**：CATIA、Ansys、Adams、VI-grade 通过 adapter 接入，但原生
   建模、网格、求解和结果仍由厂商软件完成；厂商细节不能渗透到统一对象模型里。

## 建议的交付顺序（2026-11-11 调整）

### P0：可靠地操作工程软件

- 核心产品路径：描述目标 → 选择软件与输入 → 检查计划 → 调用软件 → 回收并验证结果。
- 软件连接状态分为未配置、已配置、可连接、启动程序已找到、工程操作已实机验收。
- 显式绑定动作、脚本和启动命令；生成模板不自动视为可执行集成。
- 本机与远程 worker 使用同一文件契约，控制端无需安装全部软件或 Windows。
- 一个软件、一个最小工程任务先完成建模/求解/导出/读回，再扩展工具链。
- 执行前用 preflight 复用动作和输出契约，明确告诉工程师缺少脚本、命令、worker 动作或输入，
  避免用一次真实求解来试错配置。
- 失败返回明确原因和日志；本地结果只在全部步骤成功后统一发布。
- 实机验收记录软件版本、许可证、脚本、输入/输出和独立工程检查。

### P1：让 AI 能依据真实软件反馈迭代

- 规划只选择已配置、适用版本且具备输入的动作。
- 导入几何、更新参数、求解和结果回读逐步扩充厂商操作库。
- 收集软件报错、模型树、求解收敛状态和工程指标，支持有界修复与重规划。
- Viewer 用于查看软件生成的模型和结果，版本比较用于核对 AI 修改；它是跨软件观察层，
  不取代厂商软件内部的完整建模和后处理界面。
- 支持软件会话锁、取消、长任务轮询和断线恢复；超时不能被当作安全重试许可。

### P2：交付和使用体验

- 软件连接配置页、项目模板和逐软件运行向导。
- 大结果文件采用流式传输；保留可重放输入、原生文件和运行证据。
- 改善任务报告、时间线、指标规则和安装体验。
- 本地几何与离线演示只按预览、验证、输入准备和无软件测试的需要发展。

### P3：团队化使用

- 项目权限、凭据隔离和审计导出。
- 共享 artifact registry 和项目锁。
- MCP schema 版本协商、分页、订阅和兼容性测试。
- GitHub Actions、Windows runner 和发布安装包自动验收。

## 每个版本的验收门槛

- 新用户在干净环境中 10 分钟内完成离线闭环。
- 失败任务可以从界面定位到阶段、日志和输入文件。
- 同一项目重复执行能得到可比较的版本记录。
- 没有商业软件时，所有核心测试仍然通过。
- 接入真实软件时，替换的是 adapter/worker，不能改变 Web、MCP 和验证接口。

## 接下来的三件事

1. 连接配置页和逐软件能力清单。
2. CATIA 最小建模/修改/导出/读回任务的实机验收，随后接 Ansys 求解与回读。
3. 在已有持久软件任务基础上补厂商会话停止确认、整条计划续跑和大结果文件传输。

## 已交付：任务详情与报告

- 任务详情页：实际阶段耗时、原输入与规则、执行计划、指标、产物和事件。
- HTML/JSON 下载：HTML 自包含并支持浏览器打印，报告区分执行状态与指标结论。
- 失败重试：输入快照、原任务关联、活动重试去重、同模式执行。
- 每次运行的历史产物副本与 SHA-256，在原事务内一起提交。
- Web 和 CLI worker 共享执行入口与原子认领；项目任务先过滤再分页。
- 新数据库字段自动迁移，旧记录缺失的信息不推测补齐。

下一阶段仍需完成软件连接配置页、真实 Windows worker 验收、整条计划的中断续跑，以及
长期项目的历史产物清理策略。当前阶段没有验证商业软件的真实求解。

## 本轮：软件执行契约

本机与远程共用版本化协议；令牌校验、输入脚本传输、隔离作业目录、日志、输出完整性、
历史副本和事务发布已有受控程序测试。访问健康端点只提供连接与启动条件证据，
不标记许可证或厂商操作已验证。具体契约和已知限制见 `SOFTWARE_INTEGRATION.md`。

## 已实现：远程软件长任务

- 持久任务编号、请求摘要与幂等提交，独立监督进程不依赖 HTTP 连接。
- 同 worker 根目录的同种软件按序执行，活跃系统锁与持久占用分工，异常后保留待核实状态。
- 状态、日志、事件与任务列表分页；取消 runner，显式核实并解除占用。
- 提交响应丢失后查询原编号；单步结果重连、外部修改冲突检测、结果与回收记录事务提交。
- Web 查询/日志/取消/回收/核实页面；CLI 与 MCP 对应接口，safe profile 仅查询。

这些能力经过受控进程测试。真实 Windows 运行、厂商软件会话取消和工程结果验收仍待完成。
