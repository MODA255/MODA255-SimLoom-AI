# CAD 修改、恢复与历史

本说明描述实际实现边界，不表示已与 AgentCAD 全面等价。

## 文件组和锁

CAD 写操作在取得项目锁后读取图纸，在同一锁内修改、验证、保存和重读。
DXF、`.cad.json` 与 `.engineering-agent/cad-history/` 内的历史游标一起提交。
CAD 检查和工作台预览使用同一锁，避免读到一半更新的文件组。

项目锁使用操作系统锁，进程退出后由操作系统释放；锁元数据不按时间强行过期。
长时间求解不会因为超过一小时而被另一个写入任务抢占。

提交前会持久保存每个文件的前后快照、SHA-256 和目标路径。
每个目标通过临时文件原子替换，文件内容和日志会同步到磁盘。
多个文件不是单次文件系统原子操作；一致性由项目锁和恢复日志共同提供。
不使用项目锁的外部程序仍可能在提交过程中观察到不同版本的文件。

## 失败与重启

- 落盘验证返回失败或抛出异常：恢复前一组文件及历史游标，再释放锁。
- 提交或恢复途中进程退出：下一次项目操作先读取日志、核对哈希并恢复前一组文件。
- 已持久写入 committed 状态：重启后保留此次提交。
- 外部文件变化、快照损坏或恢复清单缺失：停止恢复并保留现场，不能宣称恢复成功。
- 在一次成功提交后进行延迟 rollback：先重新加锁和检查当前哈希，拒绝覆盖后续提交。

恢复日志与快照位于 `artifacts/runs/<run_id>/`。不要在仍需要历史时删除它们。
旧事务缺乏足够的恢复清单时需要人工检查，不能安全地猜测恢复结果。

## 撤销与重做

`cad.undo` 恢复上一项修改前的文件；`cad.redo` 恢复对应修改后的文件。
这两项操作本身仍走同一事务层。撤销文件创建会删除当次创建的文件，重做会恢复。

历史在磁盘上保存，重启 Python、工作台或 MCP 客户端后仍可继续。
撤销先检查当前 DXF 和侧车文件的 SHA-256。任一文件被外部修改都会返回
`CAD_HISTORY_CONFLICT`。历史快照损坏时返回 `CAD_HISTORY_SNAPSHOT_CORRUPT`。

撤销后再次编辑会截断待重做分支，历史不冒充仍可重做。修复无效图纸后撤销，
会恢复原始无效图纸并如实返回验证失败信息；原始数据恢复和几何有效性是两个检查。

旧版程序生成且没有持久历史的修改无法追溯撤销。当前提供线性撤销/重做，
尚无任意历史版本的可视化切换或分支合并。

## 验证入口

```bash
python -m pytest tests/test_cad_transactions.py tests/test_cad_editing.py tests/test_native_dxf.py -q
```

事务测试包含真实子进程退出、跨进程 CLI 撤销/重做、并发锁冲突、验证失败、
第二个文件替换失败、外部修改、损坏快照，以及图纸和历史一起崩溃恢复。
浏览器测试见 `tests/browser/cad_editor.cjs`，通过真实鼠标点击和 API 落盘检查验证
选择、移动、旋转、文字编辑、删除、撤销/重做和页面重新加载。

Windows 锁分支使用标准系统接口；跨平台 CI 配置不代表它已在本地 Windows 实机通过。
原生 DXF 审计和几何读回验证见 [NATIVE_DXF.md](NATIVE_DXF.md)。工程图纸的 PDF/PNG 导出与失败恢复见 [DRAWING_EXPORT.md](DRAWING_EXPORT.md)。
两直线圆角/倒角还有独立连续性、相切性和尺寸检查，见 [CAD_CORNERS.md](CAD_CORNERS.md)。
真实客户图纸兼容、打印机实际输出以及四款商业软件后端仍需独立验收。
